# Telegraph Hackathon Intelligence Brief

Research snapshot: 26 August 2026. Live state can change every epoch.

## Confirmed from the team

- One participant may enter both the Miner and Application tracks and qualify for both prize pools.
- Miner/API integration is performed through `integrate.telegraphprotocol.com`.
- The final submission platform is separate and had not yet been launched when the Discord messages were captured.
- Updating a registration does not by itself harm eligibility.
- A WASM registration may not appear in the dashboard until it has been evaluated. Preserve the Base transaction hash for support and proof.
- Self-hosted, stable URLs are recommended for submission artifacts. Do not rely on an ephemeral URL.
- The simplified word-overlap scorer in the documentation is educational only, not the production baseline.
- WASM evaluation is dynamic: the current champion is rescored against the latest fixture cases whenever a challenger is evaluated. Historical leaderboard scores are not the current promotion target.

## Explorer observations

- The Explorer exposes separate Miner, intent-filtered Miner Leaderboard, WASM, Validator, and Signal pages.
- Miner leaderboard scores are displayed to three decimal places. `0.000` can therefore conceal a small non-zero score; use precise API values for diagnosis.
- A rejected WASM can have a higher visible eval score than a champion. Promotion depends on gates such as separation margin, head-to-head wins, self-match, near-miss behavior, and variance—not the headline score alone.
- Example rejection #941 showed candidate margin 0.7648 versus champion margin 0.7796 despite 15/15 candidate wins and perfect self-match.

## Implications for Tempest

1. Do not optimize against a single historical output or displayed three-decimal score.
2. Ask the team publicly for the canonical `STORM_ALERT` request, response, and ground-truth schemas plus the production reference WASM.
3. Capture every legitimate evaluation case we receive and add it as a regression fixture.
4. Keep the miner deterministic, explainable, always-on, and cheap enough to attract genuine application traffic.
5. Preserve registration IDs, wallet address, YAML content hash, deployment commit, and every Base transaction hash.
6. Enter Track 3 with an application that consumes routed Telegraph miners rather than calling Tempest directly.
